Goal

Wrap up Project 01: on time, fully featured, and actually running.

This is the final deliverable for the project. The retrospective and the presentation are separate assignments with their own due dates.

What you submit

One PDF, submitted once for the group, containing:

  • A link to your repo.
  • A link to a video of the app running. This is the same recording you use for the presentation.
  • A link to your README.

Your README has to be good enough that someone who has never seen the repo could clone it, build it, and run it: what the app does, how to build it, how to run it, and anything it needs such as an API key.

The requirements, stated plainly

"Fulfilling the requirements of Project 01" means these, and they are checked against your video and your repo.

Two of them are hard gates. Miss either one and the MVP row of the rubric is a zero no matter how good the app looks, because these are the architecture the project exists to teach:

  • Local storage is Room or SQLite on the device. Not Firebase, not a remote store.
  • The UI is Kotlin Compose. Not XML layouts.

The rest is judged on how much of the core loop your video actually demonstrates:

  • A user can log in and see something specific to them.
  • The app consumes a real external REST API. You may not write your own API.
  • Information persists across restarts of the app.

How this is graded

See the rubric. It has two kinds of rows:

  • The [TEAM] rows are the same for everyone in the group: whether the app meets the requirements above, whether the repo shows the process (issues closed through pull requests, branches rather than main, reviews submitted before merges, tests that exist), and whether the video and README do their job.
  • The [YOU] rows are graded per person, from your GitHub activity across the whole project: your merged pull requests, issues assigned to you that you closed, and reviews you actually submitted on teammates' work. Teammates will receive different grades on this assignment.

On contribution, so nobody is surprised

The project spec has said from the start that individual contribution to the repo is a major part of how this project is evaluated. Here is exactly how that is measured:

  • A pull request counts as yours when the commits inside it are yours. Opening a pull request that carries a teammate's commits is not a contribution, and it will be scored as one.
  • Merging a teammate's pull request is not a review. A review means you submitted one on GitHub, with comments that engage the code.
  • Closing issues counts when your own merged work closed them.

I read this straight from the repository, per student, across the entire project. If you have been doing the work, this is free points. If you have not, this is where that shows up, and "I didn't do anything because..." is not going to cover it.

What loses points

  • A video that does not show the app actually running.
  • A README nobody could build from.
  • Dead links. Check them before you submit.
  • Work that landed on main without pull requests, or merges with no review attached.
